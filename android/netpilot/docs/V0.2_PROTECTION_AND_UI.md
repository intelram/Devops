# NetPilot 0.2: on-phone protection VPN and simplified interface

Supersedes the permission list, the screen description and the "no VPN" scope in `DESIGN.md`. The failover,
diagnosis and split-download parts of `DESIGN.md` still apply.

## What changed for the user

| Before (0.1) | Now (0.2) |
|---|---|
| One screen of technical text (`PREFER_WIFI`, network IDs, ms timings) | Four tabs: **Home**, **Protection**, **Connection**, **Settings**; technical details moved under *Show advanced options* |
| Start/Stop buttons | One big **Connect** button (animated, labelled, TalkBack-friendly), Quick Settings tile, notification actions (Pause 5 min / Turn off) |
| No ad blocking | Device-wide blocking of ads, trackers and harmful sites through an on-phone VPN |
| Raw diagnosis codes | "Needs attention" card in plain words with a **Fix it** button that opens the right Android setting |
| Technical event log | Plain connection history ("Wi-Fi is connected but has no internet", "Phone switched to mobile data") |
| — | Live download/upload speed, response time, mobile-data use since restart, battery-setting check |
| — | Guided 3-page introduction, dark mode, 48 dp touch targets, AA contrast, headings and live regions for screen readers |

## How the protection works

```
 any app ──DNS query──► 10.111.222.1 (NetPilot TUN, DNS only) ──► check lists ──blocked──► 0.0.0.0 / :: answer
                                                                     │
                                                                     └─allowed──► DNS-over-HTTPS (Cloudflare/Quad9/Google/Mullvad/custom)
                                                                                    └─fails? optional plain DNS of the current network
 any app ──web/video/app traffic──────────────────────────────────────────────► Wi-Fi or mobile data directly (never enters the tunnel)
```

- **DNS-only tunnel.** The VPN routes only its own DNS server addresses (one IPv4 /32, one IPv6 /128), so normal
  traffic keeps full speed and the VPN costs little battery. Optional: also route eight well-known public resolvers
  (8.8.8.8, 1.1.1.1, …) for apps that skip the phone's DNS.
- **Lists** (downloaded at runtime, never bundled): StevenBlack unified hosts (ads and trackers, on), HaGeZi
  Threat Intelligence medium (harmful sites, on), HaGeZi Multi PRO (stricter, off). HTTPS only, ETag
  conditional requests, size cap, rejected if suspiciously small, previous list kept on failure, daily refresh.
  A 70-domain built-in starter list covers the time before the first download.
- **Compact matching.** Lists compile to sorted 64-bit hashes. Measured on the real 623,471-domain HaGeZi list (JVM):
  about 1 s to parse, 0.8 µs per lookup, about 5 MB kept in memory. Parent domains match too
  (`ads.example.com` blocks `x.ads.example.com`).
- **Exceptions.** User allowlist (always wins) and blocklist. Allow/block straight from the activity list.
  "Pause for 5 minutes". Per-app bypass (Android's disallowed-apps list; launchable apps only, via `<queries>`).
- **Encrypted DNS.** RFC 8484 POST, normal certificate validation, system CAs only (user-installed CAs can't
  intercept). Plain-DNS fallback is on by default so captive portals work. The UI says when the fallback is in use.
- **Honest statistics.** Exact counts of lookups checked and blocked, not "ads". Activity list in memory only.
- **Always-on VPN** supported (`SUPPORTS_ALWAYS_ON`). When Android manages it, the app sends the user to VPN settings instead of disconnecting.
- **Single VPN slot.** If another VPN is active, the user is warned before NetPilot takes the slot. If another app
  takes it later (`onRevoke`), NetPilot posts a notification.

## Known limits (stated in the app)

- Not bandwidth bonding. Android decides which connection other apps use; NetPilot monitors and alerts.
- DNS blocking can't remove ads served from the same domain as the content (e.g. YouTube).
- **Strict Private DNS** (a provider hostname) and browser "secure DNS" with a custom provider send lookups around
  NetPilot. The app detects strict Private DNS and shows a fix.
- Lookups over DNS-over-TLS/TCP to the tunnel address aren't answered (UDP only). Resolvers fall back to UDP.
- Apps can't be attributed per DNS query (Android's resolver sends lookups on the apps' behalf).

## Permissions

`INTERNET`, `ACCESS_NETWORK_STATE`, `CHANGE_NETWORK_STATE`, `FOREGROUND_SERVICE`,
`FOREGROUND_SERVICE_SYSTEM_EXEMPTED` (the type Android reserves for VPN apps), and `POST_NOTIFICATIONS` (asked once,
before the VPN prompt). `FOREGROUND_SERVICE_SPECIAL_USE` and the old monitor service were removed.
No location, no `QUERY_ALL_PACKAGES`, no usage access, and no backup or device-transfer of app data.

### Device checklist (please run on the phone)
1. First launch: introduction → *Turn on protection* → notification prompt → VPN prompt → **Protected**.
2. Protection tab shows lists downloading, then "N sites · updated just now".
3. Open a news site: *Blocked today* rises; Recent activity shows blocked domains; tap one → *Allow* works.
4. *Pause for 5 minutes*: Home shows Paused with the resume time; *Turn back on now* resumes.
5. Settings → switch DNS provider; browsing still works. Turn Wi-Fi to a captive portal: sign-in page loads.
6. Choose an app to skip protection → its lookups no longer appear in the activity list.
7. Turn on another VPN app → NetPilot posts "Protection turned off".
8. Unplug the router's internet while on Wi-Fi → Home shows "Connected, no internet" and an alert notification.
9. Quick Settings tile toggles protection. Rotate the phone and switch dark mode: no resets, readable text.
10. TalkBack: Connect button reads its state, cards read their status, all buttons are reachable.
